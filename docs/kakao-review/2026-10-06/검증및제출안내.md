## 제출 전에 확인할 실제 불일치

### 로그인 개인정보 고지

실제 카카오 콘솔의 동의항목은 `profile_nickname`, `profile_image`, `account_email` **세 항목 모두 필수 동의**다. 이메일은 `[수집]` 표시도 확인했다. 실제 재로그인 요청의 scope에도 세 항목이 들어 있다. 최초 점검 당시 운영 개인정보처리방침은 카카오 식별값·닉네임만 기재했다. 이것을 이번 반려의 확정 원인으로 단정하지 않는다. **후속 요청으로 공통 개인정보 원본을 직접 보완했으며, 공개 URL의 운영 배포 본문 대조는 아직 남아 있다.**

`src/lib/auth.ts`의 `scopes: profile_nickname`은 이메일·사진을 제외하는 설정이 아니다. [Supabase Auth 공식 소스](https://github.com/supabase/auth/blob/master/internal/api/provider/kakao.go)는 이메일·프로필 사진·닉네임을 기본 scope로 설정하고 전달받은 scope를 추가한다. 해당 파일의 잘못된 “닉네임만 요청” 주석도 후속 작업에서 수정했다.

`src/data/legalDocs.ts` 제1·2·4·8·12·17조에 이메일·프로필 사진 URL, 인증·프로필 관리 목적, 수집 경로·거부 영향, 보관·삭제와 Supabase 국외 이전을 반영했다. `src/pages/AccountDeletion.tsx`의 삭제 항목도 3언어로 보완했다. 전문 상단·변경 이력에 2026-10-06 고지 보완을 표시하고 기존 시행일·LEGAL_VERSION은 유지했다. scope·새로운 수집 목적을 확대하지 않았다. 과거 동의의 적법성 또는 공지 의무 완료를 소급 확인한 것은 아니다.

로컬 공개 전문과 가입 시트의 동일 본문을 브라우저에서 확인했고, `npm run verify`와 관련 온보딩·접근성 E2E 14/14가 통과했다. [최신 스토어 준비 가이드](../../STORE.md)와 `docs/store-review/2026-10-06/`의 전문 TXT·로컬 검증 화면을 참고한다. 기존 `04-개인정보처리방침.jpg`는 최초 운영 점검 당시의 보완 전 화면이므로 수정 후 전문 증거로 제출하지 않는다.

불필요한 수집을 줄이는 방향을 선택한다면 카카오 동의항목만 끄는 것으로 끝내지 말고 Supabase 기본 scope와 신규 가입·기존 계정 로그인을 함께 검증해야 한다. 제출 자료에는 “닉네임만 요청”이라는 주장을 넣지 않았다.

| 에이전트·모델 | 현재 Codex 세션 모델로 인증·수집 고지·자료를 일관 검토. 정확한 실행 모델 ID는 도구에 노출되지 않아 임의 기재하지 않음. 추가 에이전트·다른 모델 호출 없음 |
| 자동화 | 기존 npm 검증과 E2E 실행. 새로운 반복 자동화가 필요한 요청이 아니므로 예약 생성·설정 변경 없음 |

Codex의 소유 범위는 해당 체크아웃의 점검·자료 생성·요청된 개인정보 고지 보완이다. 등록증 사본 대조와 카카오 최종 신청은 운영자의 업무로 남는다. 운영 배포 여부는 코드 수정·로컬 확인과 구분한다. 카카오 설정 저장·신청 전송, 계정 영구 삭제, 유료 기능 호출 및 새 계정 약관 동의는 실행하지 않았다.
